## 3. 本轮顺带清偿与修复

- **ResultParserService 真实弱点修复**：畸形 JSON（嵌套对象数组）被判解析失败后退化切分时，
  会放行 `[{"name":"A"` 这类语法碎片（躲过长度/空白/符号全部既有闸门）。新增
  "JSON 结构字符闸门"（含 `{}[]` 即弃——合法技术标签从不使用这些字符，零误伤）。
  由 TagParserSamplesM11Test 的 nestedStructureFailsJsonLevel 正反双向钉死。
- JaCoCo 接入：`mvn test` 自动产出 HTML/CSV 报告；`-Pcoverage-gate` 显式门槛
  （BUNDLE 60% + `com.blog.module.ai.*` 包 75%，check 绑 verify）。
- CI 升级：`mvn -B test` → `mvn -B verify -Pcoverage-gate`（覆盖率退化即红灯）。
- Windows 中文路径坑固化：JaCoCo 默认 destfile 展开含中文绝对路径后 javaagent
  静默失效（exec 永不生成且无报错），pom 以 OS=Windows 自动激活 profile 将 exec
  重定向到纯 ASCII 的 `E:/develop/jacoco/`（Linux CI 不受影响）。

## 4. 残余缺口与口径说明（诚实清单）

- `ResultParserService.LlmUsage` record 0%：纯数据壳（record 自动方法不计有效逻辑），
  由管道测试间接覆盖，不补直接断言。
- Controller 层部分 catch 分支未扳机（如 GlobalExceptionHandler 的 500 兜底行、
  BindException 路径）：这些分支的触发依赖容器行为（Tomcat 错误派发），MockMvc 无法
  自然走到；真实环境冒烟（M6~M10 各轮）已验证兜底可用。
- 实体/Lombok 生成方法占比：JaCoCo 对 @Data 生成的 equals/hashCode 记为未覆盖行，
  属工具噪音，不影响"核心 Service ≥60%"的达标结论（该口径按 service 包聚合为 93.1%）。
- 前端 Vitest 只测纯函数（utils 层）；组件渲染测试需要 @vue/test-utils 全量引入，
  毕设口径下以构建通过 + 真实浏览器冒烟（各轮）替代，记为设计内取舍。
